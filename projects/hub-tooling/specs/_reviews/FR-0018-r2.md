## AC-4 as amended, against `90646dc`

**No new git argv.** `_snapshot_paths` and `_restore_paths` only use `Path.read_bytes`, `is_file`, `exists`, `unlink`, `mkdir` and `write_bytes`. The recorded argv of a full resolution with the restore running is:
- one `merge origin/main`;
- one `add -- specs/INDEX.md`, the only `add`;
- one `commit --no-edit`.

There is no `reset`, `checkout`, `restore`, `rebase`, `stash`, `switch`, `--abort`, `--continue`, `--amend` or `--force`. Both `core.autocrlf=false` and `true` pass. Under `true`, the restored bytes are the checkout's CRLF bytes, so `git status` stays empty.

**Restore order.** In code, `_restore_paths(wt_path, side_snapshot)` runs straight after the indexer returns, before the `rc`/`unrestored` branch and before the `add`/`commit` loop. In the test, `CODEOWNERS` equals its checked-out bytes when `git add` runs and again when `git commit` runs. After the resolution:
- the worktree is clean;
- the tip's `CODEOWNERS` is the textual merge (here, the stale base, which neither side touched);
- a fresh regenerate shows ` M CODEOWNERS` and nothing else, so the case is real and `INDEX.md` is not disturbed.

**Failure paths.**
- **Indexer fails.** The side-writes are put back first, then `INDEX.md`'s conflicted bytes, then one `ERROR … exited N …; left for a human`. Covered for:
  - `CODEOWNERS` rewritten, created, or deleted, then exit 3 (D, 3 cases);
  - `INDEX.md` rewritten or deleted, then exit 3 (R, from r1, still green).

  Using `_restore_paths` for `INDEX.md` as well is a small improvement on r1. If `INDEX.md` was absent in the conflict state, an indexer-created one is now removed, where r1 left it.
- **A side-write that cannot be put back.** R drives it for real. The indexer exits 0 but leaves a directory where `CODEOWNERS` was absent, which `unlink` cannot remove. The result:
  - one `ERROR … could not put back the indexer's other output (CODEOWNERS); left for a human`;
  - `INDEX.md`'s conflict markers back, `UU`, `MERGE_HEAD` kept;
  - no `add` and no `commit` argv run, and no push.

**The two additions beyond the brief.**
1. **An unrestorable side-write gives an ERROR and stops before staging.** In scope and correct. DEC-0030 item 6 says the resolution "changes nothing but `specs/INDEX.md`". If a side-write cannot be put back, that cannot hold, so the only consistent outcome is AC-4's existing "does not apply" path: `ERROR`, non-zero exit, no push, conflict left in place. The code does exactly that. The leftover side-write is named in the line, so the human knows what to clean. It adds no git argv and no new outcome class.
2. **The N-3 rewording on a failed `commit --no-edit`.** In scope: it changes one message on an existing `ERROR` path, which r1 N-3 asked for. Correct, driven for real (R): a `pre-commit` hook refuses the commit. The line reads `… concluding the merge failed: …; specs/INDEX.md is staged and the merge is still in progress; left for a human`. Git agrees:
   - `MERGE_HEAD` is present;
   - `git diff --diff-filter=U` is empty;
   - `specs/INDEX.md` is in `git diff --cached`;
   - `CODEOWNERS` is already restored;
   - nothing is pushed.

   The tag keeps `ERROR` and never says `MERGE-RESOLVED`.

## FINDINGS

Non-blocking:

- **N-5 (AC-4): a snapshot read error is a traceback, not an ERROR.** `_snapshot_paths` runs outside the `try`, so an unreadable `CODEOWNERS` (or `INDEX.md`) raises `OSError` out of `finalize`. Nothing is lost: the merge is still in progress with `INDEX.md` unmerged, which is the "left for a human" state. But it is a traceback where every other failure is one `ERROR` line. Cheap fix: treat a snapshot `OSError` like an unrestorable side-write, with one `ERROR`, before running the indexer.
- **N-6 (AC-4): a pre-existing non-file at a side-write path.** If `CODEOWNERS` is a directory before the indexer runs, `_snapshot_paths` records it as absent. `_restore_paths` then tries to `unlink` it, fails, and reports it as unrestorable, so the resolution stops with an `ERROR` even though nothing changed. The indexer would also fail writing to a directory, so this cannot turn a success into a failure. Cosmetic.
- **Carried from r1:** N-1 (for FR-0024, now in DEC-0030's cascade), N-2, N-4, F-1, F-2.
