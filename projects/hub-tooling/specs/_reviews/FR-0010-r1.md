## FINDINGS

- (a) [asymmetry — hardening candidate] `ensure_role_worktree` refuses a malformed `owns:` only for `dev` (FR-0009 AC-5 defense-in-depth). For `rev`/`bkf` the refusal lives at the `cmd_tick`/`cmd_wave`/`cmd_oneshot` call sites (tested); a direct `spawn_role` for `rev`/`bkf` degrades to the static surface (tested: never wider). The rework loop's rev re-spawn is shielded in practice because the dev leg refuses first. Suggest a follow-up that extends the in-`ensure_role_worktree` refusal to every `owns:`-deriving role.
- (b) [scope] The rework loop (`_run_one_rework_round`) prints no per-spawn line at all, so no `STACK` line and no AC-2/AC-5 WARN preflight run for round-2+ re-spawns; grants are still correct because every path goes through `write_worktree_settings`. AC-7's "line the dispatcher prints for a spawn" does not literally exist there; noting for FR-0011/FR-0013 which touch the same call sites.
- (c) [spec] AC-7 says "immediately preceding". Two other ACs legitimately print between `STACK` and the spawn line: FR-0006 AC-12's `WOULD-FAST-FORWARD` (rev dry-run with an existing worktree) and this FR's AC-9 venv WARN (apply). Adjacency is pinned for the plain cases; the two interleavings are by design. Consider wording AC-7 as "before, on the same report".
- (d) [spec] For a project with **no** lock/requirements file, a `packages-install-failed` venv is reported once (WARN + `venv=` segment) but the next spawn returns `venv-reused` — the pre-FR unconditional fast-path AC-12 explicitly preserves. AC-9's "never left with a half-built venv silently" therefore holds fully only for lock/requirements projects (state file). AC-9 and AC-12 pull in opposite directions in this corner; the code follows AC-12. Architect may want to reconcile (e.g. record state for the bare branch too).
- (e) [security — open question 2] Confirmed live: a granted `Bash(docker *)` lets a role write role-denied paths through a bind mount (`docker run -v <worktree>:/wt …` appended to `scripts/deploy-gate.py` in the rev worktree). The FR's default (grant when compose is declared; `Bash(python *)` already offers the same escape to `dev`/`rev`) stands, but for `mnt` — whose deny list is the one that guards the control plane and whose interpreter access is deliberately narrowed — `Bash(docker *)` re-opens exactly the hole `MNT_BASH_NOT_INHERITED` closes. Recommend the Architect narrow the table to exclude `docker` from `mnt` (or gate it behind an explicit ADR `stack_tools:`), as the FR's own note invites.
- (f) [wording] `tests/test_*.py` in `owns:` is withheld for `rev`/`bkf` (same helper as `dev`, per AC-5) with the message "is a protected control-plane path; rev cannot be granted it — control-plane paths are `mnt`-only". For `rev` that path is neither control-plane nor unreachable (`Edit(tests/**)` is static). Harmless — the static grant covers it — but the WARN misleads.
- (g) [design] Detection reads `REPO_ROOT` (the outer checkout), not the per-FR worktree, so a branch that *introduces* a stack marker (an FR that adds `uv.lock`) gets no stack grants until it merges; the ADR channel likewise reads the outer `specs/decisions/`. Documented in `detected_stack_tools`; FR-0011 should keep the one call site.
- (h) [nit] `_COMPOSE_FILE_RE` is `IGNORECASE` and uses `docker-compose.*` (regex dot), so `Docker-Compose.YML` and `docker-composeX.yml` count as markers — wider than AC-1's `docker-compose*.y[a]ml` glob, harmless on a case-insensitive filesystem.
- (i) [pre-existing] In a bootstrapped project, `.claude/settings.local.json` shows as untracked inside a role worktree (template `.gitignore` ignores `.claude/worktrees/` from the outer repo only). Not this FR's; FR-0009's dogfood would have seen the same.
- (j) [ops] `uv sync … --python VENV_PYTHON_VERSION` (3.11) against a project whose `requires-python` excludes 3.11 will soft-fail as `lock-sync-failed` (open question 3's default). Operators can set `DISPATCH_VENV_PYTHON`; worth a line in the dispatcher docs when FR-0011 lands.
- (k) [ops / Windows] In a deep worktree path (the session scratchpad, ~165 chars to the worktree), `uv pip install pytest pyyaml` hit MAX_PATH inside `site-packages` and the provisioner reported `packages-install-failed` while the spawn proceeded — AC-9 observed live, and a reminder that hub worktrees under long paths need long-path support enabled for the venv, not just `core.longpaths` for git.
