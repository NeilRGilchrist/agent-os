### How the AC-1 guard treats kwargs it cannot see

- A subprocess-shaped call (`run`, `Popen`, `check_output`, `check_call` or `call`, including the injected `run` seam) that spreads `**kwargs` or `*args` is a violation outright. The guard cannot prove that the spread carries the keywords, so a later FR must pass them explicitly.
- A dict literal that sets `"text"` or `"universal_newlines"` must itself carry `"encoding": "utf-8"` and `"errors": "replace"`.
- `dict(text=True)` is a call, so the main rule covers it.
- A non-constant `text=` counts as text mode.
- `encoding=` or `errors=` on a subprocess-shaped call implies text mode. This is how the guard catches the two calls that had `encoding="utf-8"` before this FR.
- Values must be the literal constants `"utf-8"` and `"replace"`. `errors="strict"` and `encoding="cp1252"` are violations.
- The four live files contain no spreads and no kwargs dicts.

### Windows emulation, used by the deterministic bite checks

`_windows_run` runs the real command in bytes mode. It then decodes the output using the caller's `encoding=`/`errors=` if given, and otherwise as cp1252 strict. On a decode failure the output is `None`, which is what Windows' reader thread produces. Calls that pass `encoding="utf-8", errors="replace"` therefore decode exactly as real `subprocess` does. This makes the bites hold on Linux CI too. On this host (cp1252, Python 3.12.10) I also ran the "native" bites without the shim, and they fail at the base as expected.
