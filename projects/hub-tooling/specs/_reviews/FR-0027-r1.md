## Regex and backtracking

Index pattern `^-\s+\*\*AC-(\d+)[ \t]+\(((?:(?!\):\*\*).)+)\):\*\*\s*(.*)$`; gate pattern `^[ \t]*-[ \t]+\*\*AC-(\d+)[ \t]+\((?:(?!\):\*\*).)+\):\*\*` (MULTILINE).

**Shapes Terms calls labelled.** All match, and `L` ends at the **first** `):**`. Each is pinned in `_LABELLED_EDGES`:
- `)` in the label: `(a)b)`;
- `:` in the label: `(a:b)`;
- `**` in the label: `(a **b** c)`;
- backticks, including `` (`x):**`) ``, which cuts at the first `):**`;
- `):**` in the rest;
- a label that is a single `)`;
- tabs throughout;
- several spaces before `(`;
- trailing whitespace;
- an empty rest.

**Shapes that do not match.** Neither pattern matches any of:
- an empty label `()`;
- no space before `(`;
- ` :` (a space before the colon);
- `):*`;
- `)::**`;
- a `*` bullet;
- `-**` (no whitespace after the dash);
- `** AC-`;
- `AC- 1`;
- `AC-x`.

The five Terms near-misses do not match either.

**Whitespace-only label.** `( )` is accepted as a non-empty label by both tools. That is consistent with Terms, which say only "non-empty".

**CRLF.** Both tools read files with universal newlines. `parse_acs` on a CRLF string equals the LF result (tested).

**Backtracking.** The tempered dot `(?:(?!\):\*\*).)` has no nested quantifier and no overlap with what follows, so both patterns are linear. Measured on 3.12 (min of 3):

| Line | Length | Indexer | Gate |
|---|---|---|---|
| no closing `):**` | 250k / 500k / 1M / 2M chars | 74 / 157 / 808 / 1587 ms | about the same |
| `):*` repeated | 250k / 500k / 1M / 2M chars | 75 / 171 / 967 / 1302 ms | about the same |

- The gate ran 50,000 indented 200-character no-close lines (10 MB) in 3.1 s.
- A realistic 1 KB pathological line takes 0.19 ms.
- `test_pathological_lines_are_linear_not_catastrophic` pins a 5 s ceiling at 200k characters.

**Hash equality.** For all 8 pairs in `_HASH_PAIRS`, the labelled hash equals the plain rewrite's: continuation lines, an empty rest with a continuation, an empty rest, trailing blank lines, a padded label, tabs, `):**` in the rest, and FR-0001 AC-8-style backticks with nested parentheses.

The raw texts differ in two pairs, and only in whitespace (`(L) cont` vs `(L)\n  cont`, and `(L) R` vs `(L)\tR`). AC-2 promises hash equality and fixes the labelled text as `(L) R…`, which holds.

The subprocess round trip holds both ways: ratify in one form, rewrite into the other, and there is no drift warning. Relabelling does produce drift.

## FINDINGS

**Blocking**
- **K-1.** See Kick-back items.

**Non-blocking**
- **NBSP after the dash (FR-0027:AC-1/AC-3).** The indexer's `^-\s+` accepts any Unicode whitespace after the dash, for example U+00A0. The gate's `^[ \t]*-[ \t]+` accepts only a space or a tab. So `- **AC-1 (L):** R` is an AC to the indexer and not to the gate. The plain forms agree on this case (`AC_LINE_PATTERN` uses `\s+` and `AC_HEADING_PATTERN` uses `[\s*-]*`), so this asymmetry is new, if exotic. Terms say "`-` and whitespace", which does not settle it. Cheap fix: use `[ \t]+` in the indexer's labelled pattern, or `\s` (excluding newline) in the gate's. Architect's call.
- **U+2028 inside a label.** The gate's `.` matches U+2028, but the indexer's `splitlines()` splits there, so the two tools would disagree. This is theoretical; noted for completeness.
- **`test_duplicate_numbers_across_forms_behave_as_duplicate_plain_bullets` has no bite.** It passes on the base scripts. My `test_a_later_labelled_duplicate_wins_like_a_later_plain_duplicate` covers the direction that bites.
- **The `is not` asserts in `test_existing_ac_patterns_equal_their_base_ref_values` are tautological.** They cannot fail. Harmless.
- **The Developer's `_hub_fr0001_covers` scans only `*.py`.** The gate scans every `SOURCE_EXTENSIONS` suffix. My `test_every_fr0001_covers_in_hub_tests_names_ac1_to_ac12_in_any_source_file` closes that gap; today's result is the same.
- **The AC-6 edit adds a test, not just an annotation.** No existing test in the hub file builds both fixture shapes, so AC-6's "one new test that does" branch was the only conforming option. The `owns:` comment ("one annotation, nothing else") and the brief did not anticipate this.
