## FINDINGS

- **F1: a symlinked marker file counts (decided, consistent with the root rule).** AC-2 is silent on whether `<d>/package.json` may itself be a symlink. `is_file()` follows the link, so a nested symlink-to-file marker counts, exactly as a root one always has. A dangling one counts at neither level. This is pinned by `test_symlinked_marker_file_is_treated_exactly_as_at_the_root`. If the Architect wants "real file" semantics, it must apply at both levels (FR-0010 AC-1 and FR-0017 AC-1 together), not only nested.
- **F2: Windows directory junctions are followed.** On Python 3.12 / Windows, a junction `frontend -> <outside dir with package.json>` reports `is_symlink() == False`, `is_junction() == True` and `is_dir() == True`. `_nested_node_tools` therefore walks it and detects `node,npm,npx` (probed by hand; no test pins this either way). The AC says "not a symlink", and a junction is not one, so this is not a kick-back. DEC-0014 Decision 4 still holds, because git never materialises a junction from a commit, so only a local operator action in the primary checkout can create one. Architect call: add `or entry.is_junction()` (3.12+, guarded with `getattr`) if "real directory" is meant to exclude every reparse point.
- **F3: the maintainer's "order-sensitive" note is overstated.** Moving `is_symlink()` after `is_dir()` is an equivalent mutant (the tests still pass, and behaviour is identical), because the code `continue`s on either. What matters is that `is_symlink()` is checked at all, and dropping it is caught by two tests. The code is correct. Only the docstring and PR rationale overstate the ordering.
- Minor: `env_preflight._TOOL_DECLARED_BY` still names `package.json` without the nested path. This is explicitly out of scope per the FR and is noted only for the Project A checkpoint.
