## ESCALATION

**E-1, FR-0018:AC-4: the worktree indexer also rewrites `CODEOWNERS`, which AC-4 does not stage.**
- **The gap.** AC-4 says `specs/INDEX.md` is regenerated, staged and the merge concluded. `index-specs.py`'s plain mode also writes `CODEOWNERS` whenever `.agent-team/codeowners-config.yaml` exists (opt-in; the template ships only the `.example`). The spec says nothing about the indexer's other output. When the regenerated `CODEOWNERS` differs from the merged one, it is left as an unstaged modification after `git commit --no-edit`.
- **Reproduced** (R, `xfail(strict=True)`): with a config and a committed, never-regenerated `CODEOWNERS`, the resolution succeeds (`MERGE-RESOLVED`, exit 0, pushed), and the worktree is left with ` M CODEOWNERS`.
- **Why it matters.** FR-0013 AC-1's later fast-forward (`_ff_push_impl_onto_rev`) and a second `--revalidate` both refuse a worktree with uncommitted tracked changes (`_rev_worktree_dirty_paths`). So the resolution can leave the branch unable to take the Reviewer's tip without a human. That is the "worktree stays clean for the fast-forward" property `test_revalidate_writes_nothing_so_the_worktree_stays_clean_for_the_fast_forward` pins for clean merges. The pushed tip carries the merged `CODEOWNERS`, never the regenerated one.
- **How likely.** Narrow. Both sides normally regenerate `CODEOWNERS` with `INDEX.md`, and a clean textual merge of two regenerated files usually equals a regenerate. It takes a stale or hand-edited `CODEOWNERS` that merges cleanly. The failure is loud: a named `ERROR` at the next fast-forward, not a wrong commit.
- **Why the Developer cannot settle it alone.** Two defaults are defensible, and they differ in what the merge commit contains. Staging `CODEOWNERS` too widens AC-4's "staged" beyond `INDEX.md` and puts a non-conflicted path's regenerated content into a merge commit. Restoring it keeps AC-4's text but adds a step the spec does not name.
- **Recommended default.** The resolution changes nothing but `specs/INDEX.md`. Before running the indexer, record the bytes of every tracked path other than `specs/INDEX.md` that it may write (today, `CODEOWNERS`). After it, on success or failure, put back any that changed, the way the failure path already puts back `INDEX.md`. The merge commit then holds the textual merge of `CODEOWNERS`, the same as a clean revalidate merge under DEC-0011, and the worktree is clean. The xfail becomes a plain test. This does not block this round.
