## Kick-back items

1. **AC-5 — a non-list `owns:` is a footprint the indexer rejects and the dispatcher accepts (or crashes on).** `spec_footprint.parse_footprint` raises `FootprintInvalid("... owns must be a YAML list of glob strings ...")` for `owns: "src/**"`, `owns: 42`, `owns: {a: b}`. On this branch `_invalid_owns_entries` (`template/scripts/dispatch.py:4584`) returns `[]` whenever `raw` is not a list, so `dev_owns_derivation` falls through to `fr_owns_globs`, which iterates the scalar:
   - `owns: "src/**"` → `Edit(s)`, `Edit(r)`, `Edit(c)`, `Edit(/)` written to the settings file, two bogus WARN lines about `'*'` being protected, `owns-grants=4`, spawn proceeds.
   - `owns: 42` → `TypeError: 'int' object is not iterable` raised out of `_dev_owns_preflight`, which aborts the entire `tick` / `wave` run (every other runnable FR in the same tick is dropped with it). Pre-FR, `dev` never touched `fr_owns_globs`, so this traceback is new.
   - `owns: {a: b}` → `Edit(a)` / `Write(a)`.
   This contradicts AC-5's "the indexer and the dispatcher never disagree about which footprints are legal". **What would satisfy me:** in `_invalid_owns_entries`, treat `raw is not None and not isinstance(raw, list)` as invalid with the indexer's own message (simplest faithful reuse: call `spec_footprint.parse_footprint(meta)` for the `owns` half, or replicate its "must be a YAML list of glob strings" check), so that `tick`/`wave` print one ERROR and skip the FR and `ensure_role_worktree` refuses. The three failing parametrisations of `test_non_list_owns_is_refused_like_the_indexer_and_never_crashes_the_tick` encode exactly this and must go green; `test_fr_owns_globs_is_unchanged_by_the_frontmatter_refactor` must stay green (do not change `fr_owns_globs` itself — `mnt` depends on its current shape). No other file needs to change.

Nothing else blocks. Round 2 should only need the AC-5 fix plus re-running the suite; the coverage table above stands as-is.
