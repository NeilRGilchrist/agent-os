## Request changes

FR-0020 @ `12996e8` is correct on AC-1, AC-2, AC-3, AC-4, AC-6 and AC-7, and on AC-5's happy paths. One defect blocks approval. Managed-block marker detection in `_gitattributes_merge` (`scripts/bootstrap.py:1449-1460`) uses a raw `str.find` of each marker text **including its trailing `\n`**, and takes only the first match. Two AC-5 cases go wrong because of this:

1. **Duplicated markers are silently "replaced" instead of reported as drift** (dispatch brief, AC-4/AC-5: "Damaged or duplicated markers produce drift warnings and no overwrite").
   - `BEGIN,END,BEGIN,END`: the first span is replaced and the second stale "managed" block stays below it as project lines. Under git's later-line-wins rule, that stale block shadows every future template change to the block.
   - `BEGIN,BEGIN,END` and `BEGIN,END,END`: rewritten without a drift line. `BEGIN,END,END` leaves a stray `END` marker outside the block.
   - Failing tests: `test_duplicated_markers_are_drift_and_never_overwritten[two-blocks|two-begins|two-ends]`.
2. **A managed block that is present but CRLF gets a second block inserted on top** (AC-5, "Present with both markers ... replaced").
   - `"...BEGIN/END\r\n"` does not contain the needle `"...BEGIN/END\n"`, so both markers read as absent and the `inserted` branch fires. The file then has two blocks, and the old CRLF one sits below as project lines that override the new one.
   - Every later run finds the LF block and is "stable", so the damage never surfaces.
   - Failing test: `test_crlf_checked_out_managed_block_is_not_treated_as_absent`.

**What would satisfy me:**
- Detect markers line-wise: compare each line with its line terminator stripped (`rstrip("\r\n")`) to the marker text.
- Treat the file as well-formed only when there is exactly one BEGIN line and exactly one END line, with BEGIN first.
- Treat zero of both as "insert".
- Treat anything else (one only, reversed, duplicated) as `damaged`, which means drift line and no write.
- For a CRLF block that is otherwise well-formed, either replacing it in place or reporting drift satisfies the test. Neither may insert a second block.
- The four failing tests above must pass unedited, and the other 69 must stay green.

**Should-fix while in there (non-blocking):** the unresolved-stack notice (`resolve_stack`, `bootstrap.py:916-933`) says the two paths "are compared byte-for-byte against the template this run". In fact they are **seed-only**: never overwritten, and reported as drift. The AC-2 check passes (it names both paths and says the stack is unknown), but a human reading it would expect a clobber. Suggested wording: "...are left unchanged (reported as drift if they differ) this run."
