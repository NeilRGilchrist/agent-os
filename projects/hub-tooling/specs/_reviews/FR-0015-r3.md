## FINDINGS (consolidated, rounds 1 to 3; none blocks)

Architect-bound spec gaps:
1. **Re-running finalize after `--revalidate` falsely refuses (AC-2).**
   - After AC-7 merges an upstream change to a protected path, and while local `main` is behind `origin/main`, the next `finalize --role dev` blames the branch for upstream work.
   - The fix is a spec choice: diff against the merge-base with `origin/main`, or exclude paths the merge brought in.
   - `mnt`'s footprint check has the same class of problem on its first `--revalidate` run. That is pre-existing FR-0013 behaviour.
2. **Committed off-limits paths under a broad `mnt` `owns:` glob pass.** This is K1's committed-side twin.
   - `mnt_footprint_violations` is frozen by DEC-0017 Decision 4 and uses plain `fnmatch`. So a committed `CLAUDE.md` under `*.md`, or `scripts/deploy-gate.py` under `scripts/*`, reaches a PR.
   - This needs an AC or DEC, perhaps with IDEA-0088.
3. **Non-ASCII path names evade AC-2 and AC-3.**
   - git's default `core.quotePath=true` prints such a path quoted and octal-escaped, so it does not match `.agent-team/**` under `fnmatch`.
   - A new non-ASCII-named file under `.agent-team/`, committed or untracked, is therefore not refused.
   - The fix would be `-c core.quotePath=false` or `-z`. Whether AC-3's "same git commands" wording permits that is the Architect's call.
4. **`fnmatch` versus harness glob semantics under `mnt`** (FR-0009, pre-existing).
   - `fnmatch`'s `*` crosses `/`, so `owns: [".agent-team/*"]` counts nested files as owned.
   - The harness's `Edit(.agent-team/*)` does not match nested paths. This belongs with the IDEA-0088 / FR-0009 follow-up.

Wording and cosmetics:

5. **The AC-1 `NOTE` also prints when no Reviewer was involved.** For example, it prints on the maintainer's own commit. The refusal is correct, but the wording misleads.
6. **The AC-4 wording for a corrupt record.**
   - The prefix "permission file changed since it was written: <record> …" blames the permission file when the record is what failed.
   - Round 3's type-check line reads "is missing 'path' or 'sha256' (or either is not a string)". It does not name the offending key.
   - A NUL escaped inside `path` is reported as `<path> missing`, because `Path.exists()` returns False for it. That refusal is correct but vague.

Low priority and pre-existing:

7. **Stale AC-4 records.**
   - `_record_settings_digest` silently keeps the previous record when read-back fails.
   - `reconcile` never removes records, so a hand-recreated worktree inherits a stale record and refuses.
8. **`spec_footprint._validate_glob` accepts a Windows-absolute `owns:` entry** such as `C:/x` (FR-0009). This is out of scope for FR-0015.

For the record:

9. **Harness and `uv run python -c`.** These are not blocked, and `docker run -v` writes through the bind mount. This confirms DEC-0014's code-reading assertion live.
10. **Defence in depth.** AC-2 refuses the Reviewer's finalize before FR-0013's AC-1 fast-forward. AC-1's scenario is therefore reachable only through a hand or pre-FR-0015 fast-forward.
