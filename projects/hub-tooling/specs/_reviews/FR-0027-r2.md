## FINDINGS

Still open and non-blocking, for the Architect:

- **NBSP after the dash (FR-0027:AC-1/AC-3).** The indexer's `AC_LABELLED_LINE_PATTERN` uses `^-\s+`, which accepts any Unicode whitespace (for example U+00A0) after the dash. The gate's `AC_LABELLED_PATTERN` uses `^[ \t]*-[ \t]+`, which accepts only a space or a tab. So `- **AC-1 (L):** R` is an AC to the indexer and not to the gate. The plain forms agree on this case, so the mismatch is new, if exotic. Terms ("`-` and whitespace") do not settle it. The cheap fix is to align the two character classes, in either direction.
- **U+2028 inside a label.** The gate's `.` matches U+2028, but the indexer's `splitlines()` splits there, so the two tools would disagree. This is theoretical; noted for completeness.
- **The AC-6 Reviewer edit adds a test, not just an annotation.** No existing test in `tests/unit/scripts/test_bootstrap_profiles.py` requests both `profiled` and `unprofiled`. AC-6's "or on one new test that does" branch was therefore the only conforming option. I added `test_both_fixture_shapes_are_built_under_tmp_path_and_are_distinct`, +23 lines and nothing else changed. The FR's `owns:` comment ("one annotation, nothing else") did not anticipate this. The Architect may want to align that comment with AC-6's text.
