# FR-0012: Headless conduct contract in the generated role commands

## Why

A dispatched agent runs under `claude -p`. There is no human in the session, so a turn that ends with a question ends the phase, and the dispatcher logs it as a success. That exact failure has now happened four times across two waves: the FR-0015 Developer on 2026-09-13, the FR-0001 Developer denied `Write(.python-version)` ("Could you approve the Write tool call?", 2 minutes, phase dropped, `dispatch.run status=success`), the round-1 Reviewer that hit denied `uv sync` / `npm ci` / `docker`, and today's round-2 maintainer whose `pip install` into `.venv-dispatch` was denied. None of the five generated role commands says a word about running headless. They were written for an interactive session and are dispatched into one that has no user. FR-0010 and FR-0011 remove most of the denials, but not all of them: harness-guarded paths, `gh`, and host policy still deny, so at the observed rate of two asks per wave over the twelve remaining Project A FRs, even a quarter surviving is one and a half to two hours of dropped phases. The same gap shows up as silent behaviour rather than a stop: the Developer that swapped the database driver because Smart App Control blocked a wheel made an architecture-adjacent choice no ADR had made and did not raise it as a finding, costing a decision record, a chore PR and a Reviewer round (L11); the round-2 Developer used bare `git stash`, whose stack is shared across every worktree and session on the host (L22); an agent ran a blanket `" - "` to em-dash substitution that briefly mangled `@covers` annotation lines (L45); a test that pinned five live register rows by mutable class went red within the hour (L44); and both the maintainer and the Reviewer had to be told by hand that the gate's appended `specs/_metrics/*.ndjson` record is committed only from `main` (L36, L40). Finally, the auto-mode classifier refuses `gh pr review --approve` on the owner's own PR, and GitHub downgrades a self-review to a comment anyway, so the "Reviewer approves; human merges" sentence in the commands describes something the factory cannot do (L24).

## What

After this FR lands, each of the five generated role commands carries one canonical headless-conduct block, identical in every copy, stating what an agent does when the harness or the host says no: a denied call is a hard stop for that path or a structured `## ESCALATION`, never a question; no bare `git stash`; a dependency or tool substitution the host environment forced is at least a `## FINDINGS` item; the gate's appended metrics record is restored on a role branch and committed only from `main`; and no blanket regex substitution across files carrying `@covers` / `@implements` annotations. The Reviewer and its backfill variant additionally learn that a live-data anchor asserts existence and well-formedness, never a mutable field. The reviewer and orchestrator commands restate the review contract as it actually works: the Reviewer posts the verdict of record, the human approves and merges. The `.claude/` and `.cursor/` wrappers are regenerated from those sources by the bootstrapper, and every canonical command gains both wrappers — closing the gap where three of them have only one or none today.

## Acceptance criteria

Each AC must be independently testable. Number them; the numbers are stable for the life of the FR.

- **AC-1:** **One canonical block, byte-identical in all five sources.** `template/.agent-team/commands/{developer,reviewer,maintainer,reviewer-backfill,orchestrator}.md` each contain a headless-conduct block delimited by a stable heading. The block's text, from its heading through its last line, is byte-identical across all five files apart from a single optional role-specific sentence that AC-7 permits in the two reviewer commands. Verified by extracting the block from each file and comparing.

- **AC-2:** **A denied call is a hard stop or an escalation, never a question.** The block states, in substance: you are running headless under `claude -p`; no human can answer you; never end your turn with a question; a denied tool call is a hard stop for that path — work around it inside your footprint, or emit a structured `## ESCALATION` block per `.agent-team/escalation-matrix.md` into your handoff artifact (`PR_BODY.md` for `dev`/`mnt`/`bkf`, `REVIEW.md` for `rev`) and continue with everything that does not depend on it. Verified by content assertion in all five files.

- **AC-3:** **Bare `git stash` is forbidden, with the sanctioned alternative named.** The block states that `git stash` with no arguments is forbidden because the stash stack is shared across every worktree and session on the host, and names both alternatives: a WIP commit, or `git stash push -m <tag>` followed by applying by SHA. Verified by content assertion in all five files.

- **AC-4:** **A host-forced substitution is at least a `## FINDINGS` item.** The block states that any dependency, driver, tool or version the agent substituted because the host environment refused the declared one is recorded as a `## FINDINGS` item in the handoff artifact at minimum, naming what was declared, what was used instead, and the host behaviour that forced it — and that a substitution with architectural reach is an `## ESCALATION`, not a finding. Verified by content assertion in all five files.

- **AC-5:** **The metrics record is committed only from `main`.** The block states that running the deploy gate appends a record to `specs/_metrics/*.ndjson`, that this append is never part of a role branch's handoff, and that the agent restores it (`git checkout -- specs/_metrics`) before staging — the Orchestrator commits metrics from `main`. Verified by content assertion in all five files.

- **AC-6:** **No blanket substitutions over annotation-bearing files.** The block states that scripted or regex substitutions applied across more than one file are forbidden over any file carrying `@covers` or `@implements` annotations, and that such edits are made file by file with the diff read back. Verified by content assertion in all five files.

- **AC-7:** **Live-data anchors assert structure, not mutable fields.** `reviewer.md` and `reviewer-backfill.md` state that a test anchored on live data — a register row, a spec's frontmatter, a committed artifact — asserts existence and well-formedness, never a mutable field such as a status, class, count or SHA, because another agent may legitimately change it within the hour. This is the one rule that may appear as a role-specific sentence inside the block (AC-1) or as an adjacent block; it must not appear in `developer.md`, `maintainer.md` or `orchestrator.md`.

- **AC-8:** **The review contract is restated as the factory actually works.** `reviewer.md` and `orchestrator.md` state that the Reviewer posts the verdict of record — its final assistant message, which the dispatcher posts to the PR and records as `REVIEW.md` — and that the human approves and merges; neither file instructs any agent to set a GitHub approval state on the project owner's own PR, and both note that a self-review is downgraded to a comment. The existing dispatcher-configured / no-dispatcher split in `reviewer.md` is preserved: the no-dispatcher branch keeps its `Approve` review-state instruction, which is the case where a human reviewer is not the PR author. **Revised by DEC-0019 (v4, breaking):** the parenthesis now reads "its final assistant message, which the dispatcher posts to the PR; the Reviewer's own staged `REVIEW.md` is kept as the review of record, and the dispatcher synthesises one from that message only when the Reviewer wrote none (DEC-0001, DEC-0018)". The `_ac8_gaps` detector drops FR-0006's retired `REVIEW.md` phrases. The "extended, not replaced" check covers the bullet through "The dispatcher posts that message to the PR as the review". Implemented by FR-0022 AC-2. **Revised by DEC-0033 (v5, breaking):** the third sentence now reads: the existing dispatcher-configured / no-dispatcher split in `reviewer.md` is preserved. The no-dispatcher branch records the verdict and review in a committed `REVIEW.md` and may post it as a plain comment. It sets no review state (FR-0030 AC-1, DEC-0032). The dispatcher-path parenthesis and the `_ac8_gaps` detector are unchanged.

- **AC-9:** **Every canonical command has both wrappers, regenerated from source.** After running `scripts/bootstrap.py --upgrade <project>` (or a fresh bootstrap), `.claude/commands/<name>.md` and `.cursor/commands/<name>.md` exist for every `.agent-team/commands/<name>.md`, and each wrapper differs from its source only by the generated-file banner, the frontmatter block `generate_commands` adds, and — for the Cursor variant — the `$ARGUMENTS` to `{{args}}` substitution. Verified for all twenty wrapper paths this FR owns — both harnesses for each of the ten canonical commands, including the four whose template wrappers were pre-full-body stubs and `docs.md`, whose wrappers were missing under both harnesses (**revised by DEC-0004, v2**). No wrapper is hand-edited: the committed wrappers equal the generator's output byte-for-byte after normalising `\r\n` to `\n` — `generate_commands` emits CRLF on Windows (a `scripts/bootstrap.py` defect of the FR-0007 class, routed to IDEA-0063; not this FR's to fix), so the test normalises the generated bytes before comparing. **Revised by DEC-0016 (v3, breaking):** a source may open with its own frontmatter block (FR-0019). The wrapper's frontmatter is then rendered from that block, and the wrapper body equals the source text after the block and its following blank line.

- **AC-10:** **Nothing else in the five commands changes, and no behaviour is redefined.** Apart from the added block, AC-8's restatement, and the regenerated wrapper frontmatter, the five sources are unchanged: every existing instruction — the staging contract FR-0006 AC-7 put in `developer.md` and `reviewer.md`, the maintainer footprint rules, the backfill prohibitions, the orchestrator's wave-first default and hard limits — survives verbatim. This FR changes no role's permitted footprint, no permission list, and no dispatcher code; `template/scripts/dispatch.py` is read, not edited. Every test that passed before this FR still passes. **Revised by DEC-0016 (v3, breaking):** this AC states what *this FR* changed. Its residual check compares the pre-FR sources with the sources at FR-0012's merge commit `f037978`, not with the live files, so later FRs may edit the five commands under their own ACs. The named instructions above must still survive verbatim at HEAD.

## Out of scope

- Any change to `template/scripts/dispatch.py` or to any permission list. FR-0010 owns the grants; this FR owns only what the agent is told.
- Any change to `template/.agent-team/roles/*.md`, `escalation-matrix.md` or `handoff-protocols.md`. They are read; if the Developer finds one of them contradicts an AC here, raise it under `## FINDINGS` rather than editing it.
- The canonical **sources** `template/.agent-team/commands/{architect,docs,escalate,gate,status}.md`. They are not dispatched headless into a build lane and their bodies do not change. Their **wrappers** are in scope: AC-9 regenerates them from those unchanged sources, and from v2 (DEC-0004) `owns:` lists all ten so the generator's whole output can be committed.
- Giving the factory a bot identity so a formal GitHub review is possible (Project A L24). That is a separate human decision about credentials, not a text change.
- Classifying a run that ended with a question as `stopped-needs-input` in the metrics log (Project A L28). Same root cause, different code path, not promoted.
- Changing `generate_commands` in `scripts/bootstrap.py`. AC-9 asserts its existing behaviour reaches every command; if it does not, that is an escalation, not an edit.
- Emitting the conduct block into dispatch briefs at spawn time rather than into the commands. The commands are what `/developer FR-XXXX` loads; briefs are per-run and already restate rules by hand.

## Open questions

- **Q:** Should the block also forbid `rm -rf` and mandate `git rm` for tracked files, as the hand-written Project A briefs do?
  - **Default:** No. Those are already denied by every role's permission list, so stating them in prose adds length without adding enforcement. The block covers what the harness cannot deny.
- **Q:** Should `orchestrator.md` carry the full block, given the Orchestrator usually runs interactively?
  - **Default:** Yes (AC-1). It dispatches subagents and writes their briefs; an Orchestrator that knows the contract writes briefs that carry it, which is exactly what the FR-0001 wave's hand-written briefs had to do from scratch.
- **Q:** Where does an agent put an `## ESCALATION` when it has no handoff artifact yet?
  - **Default:** It creates the artifact (`PR_BODY.md` or `REVIEW.md`) containing only the escalation block, and stages it. An escalation that exists only in a final message is invisible to the next role, which is universal rule 3 ("artifacts, not chat").
- **Q:** Should the block be generated into the wrappers from a single shared include rather than repeated in five sources?
  - **Default:** No. `generate_commands` has no include mechanism and adding one is a `scripts/bootstrap.py` change. AC-1's byte-identity test is the cheap enforcement; revisit if a sixth command needs it.

- **Regenerate, don't hand-edit.** `scripts/bootstrap.py::generate_commands` writes both wrappers from every `.agent-team/commands/*.md` with no per-command selection, so a regeneration touches all ten commands' wrappers. The template's checked-in wrapper set was stale in two ways when this FR was drafted (the v1 text named only the first): `.cursor/commands/` had no `maintainer.md` or `orchestrator.md` and neither harness had `docs.md`; and the `architect`, `escalate`, `gate` and `status` wrappers under both harnesses were pre-full-body stubs (`Follow the instructions in @.agent-team/commands/<name>.md.`) that the current generator cannot produce. Every bootstrap and `--upgrade` runs `generate_commands` after syncing the template, so no project ever ran the stubs — but `--upgrade` diffed each project's good wrapper against the template's stub and reported eight spurious updates per run until the template caught up. `.claude/**` is harness-guarded, so the grant may read as unwritable; the sanctioned route is to edit the canonical source and regenerate (`mnt_unwritable_hint` says exactly this).
