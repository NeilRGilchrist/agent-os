# FR-0022: Wave-1 craft rules become default behaviour in the role commands

## Why

In hub-tooling's wave 1, three defects survived adversarial suites of 135+ tests. Each was caught only because a dogfood run used the bare invocation, a real gate, or a real host:
- FR-0011: a loopback-only listener was invisible to the port probe;
- FR-0013: the revalidate gate ran in the wrong checkout;
- FR-0008: `gate pass` without `--note` wrote unreadable evidence.

Five of the twelve escalations were predictable assertion overlaps between an FR and an earlier FR's tests, each costing an Architect pass. The rules that prevent both were learned the hard way and now live in three places, none of them the commands:
- the Orchestrator's per-brief watch-outs (wave-2 plan §5);
- Project A's local DEC-0044, which is `provisional_until` the template reviewer command adopts it;
- one Orchestrator's memory.

The reviewer command also gives wrong advice. It tells every dispatched Reviewer "do not write `REVIEW.md`". Yet DEC-0001 made the Reviewer's own `REVIEW.md` the artifact of record, FR-0013 AC-2 preserves it, and the command's own conduct block names `REVIEW.md` as the Reviewer's handoff artifact.

Finally, a spec commit that widens a set a test pins as a literal turns the verification suite red on the base branch the moment it lands. That happened three times in one Project A week, and the DEC template says nothing about it.

## What

After this FR, each of the four role commands carries the craft rules for its role in its own section, outside the headless-conduct block:
- **reviewer:** test craft;
- **architect:** spec craft;
- **orchestrator:** brief and budget craft;
- **developer:** self-verification.

Every project inherits them on its next `--upgrade`. The reviewer command asks the Reviewer to write and stage its own `REVIEW.md` (DEC-0018, DEC-0019). The DEC template's Cascade guidance names the pinned-literal cost. The wrappers are regenerated LF by FR-0019's generator.

## Acceptance criteria

Each AC must be independently testable. Number them; the numbers are stable for the life of the FR.

- **AC-1:** **The reviewer command carries the test-craft rules.** `template/.agent-team/commands/reviewer.md` gains one section, outside `## Headless conduct` and before "When all tests pass:", with one bullet per rule. Each bullet contains the operative phrases listed for it:
  - (a) **Bare invocation.** Phrases: "only its required arguments", "real entry point". For every AC that names a CLI invocation, drive it once through the real entry point with only its required arguments.
  - (b) **Real failing check.** Phrases: "run it once for real", "built to fail", "`## FINDINGS`", "never a silent stub". For every AC that names a check, lint, gate or pre-flight, run it once for real, unstubbed, against input built to fail it, and assert the documented failure. If that is impossible, record it as a `## FINDINGS` item, never as a silent stub.
  - (c) **Bite check.** Phrases: "second module", "fail against". Load the base branch's version of the script under change as a second module (`git show <base-sha>:<path>`), show the new tests fail against it, and record the result in `REVIEW.md`.
  - (d) **Signature-faithful doubles.** Phrases: "`inspect.signature`", "compiled `.exe`", "`.bat`". A double for a function the code calls binds its arguments with `inspect.signature(...).bind`. Stub `subprocess` for `gh` before any finalize drive. On Windows a fake executable must be a compiled `.exe`, because `subprocess.run(shell=False)` does not resolve a `.bat` or `.cmd` stub, and the real tool runs.
  - (e) **Throwaways.** Phrases: "short path", "`core.longpaths`", "bare repo", "`git remote add`". Dogfood throwaways go on a short path or with `core.longpaths`. A throwaway that needs `origin` is cloned from a bare repo, never given one with `git remote add`.
  - (f) **Pin shape, not accident.** Phrases: "prefix", "explicit parameter value", "default". Pin prefixes and segments of compound fields. Pin an out-of-scope guard at an explicit parameter value, never at a default a later FR may own.
  - (g) **Derive stated vocabularies** (IDEA-0075, Project A DEC-0037). Phrases: "stated exactly once", "floor subset", "near-miss", "member shape", "clause found", "pinned as literals". A closed member set that an AC states exactly once as a brace clause is derived from the AC text by a helper and guarded by four sentinels: floor subset, near-miss denylist, member shape, clause found. ADR-governed vocabularies, grammars and any set the template owns stay pinned as literals.
  - (h) **Keep the dogfood.** Phrase: "even when unit coverage is complete". The AGENTS.md dogfood step runs even when unit coverage is complete.

  No new line in `reviewer.md` may contain `gh pr review`. `--approve` may appear only as "does not permit `--approve`", and any line containing "review state" must also say "do not set" or "never sets" (`test_neither_file_instructs_an_agent_to_set_an_approval_state_on_the_owners_pr`). Verified by phrase assertions per bullet, a placement assertion, and those constraints.

- **AC-2:** **The Reviewer is asked for its own `REVIEW.md` (DEC-0018, DEC-0019).** The dispatcher-configured verdict bullet (the single line containing "If a dispatcher is configured**: your final assistant message") keeps, verbatim:
  - its opening through "The dispatcher posts that message to the PR as the review";
  - its AC-8 clauses: "do not set a GitHub approval state", "authored by the same account", "GitHub does not permit `--approve` or `--request-changes`", "falls back to posting your verdict as a comment".

  It replaces "and records it on your branch as `REVIEW.md` — do not write `REVIEW.md` or post the review yourself" with instructions to:
  - write the full review (per-AC findings, defects with `file:line`, `## FINDINGS`, `## ESCALATION`) to `REVIEW.md` at the worktree root, and stage it on either verdict;
  - know that the dispatcher keeps a staged or committed `REVIEW.md` byte-for-byte, and synthesises one from the final message only when none was written;
  - not post the review yourself.

  The line contains neither `git commit` nor "review state on the PR". The no-dispatcher bullet, the staging-contract bullet (step 3) and every `_SURVIVING_LINES` entry are unchanged. Verified by the DEC-0018 and DEC-0019 cascade tests.

- **AC-3:** **The architect command carries the spec-craft rules.** `template/.agent-team/commands/architect.md` gains bullets that apply to both drafting an FR and responding to an escalation. Each contains its operative phrases:
  - (a) Phrases: "test specification", "double", "drive". Write each AC as a test specification: name the double, the stream and the drive where the behaviour needs one.
  - (b) Phrases: "exact-equality pins", "pre-write the DEC", "test ids". Before drafting, grep earlier FRs' tests for exact-equality pins on anything the new FR changes, and pre-write the DEC with its cascade as a list of test ids.
  - (c) Phrase: "isolation seam". Name an isolation seam for any host-touching behaviour.
  - (d) Phrases: "blast radius", "`owns:`". An AC's verification tool must have a blast radius that fits `owns:`.
  - (e) Phrase: "live for the first time". Flag helpers the FR makes live for the first time.
  - (f) Phrase: "same commit". A DEC cascade that names a test file another FR's Reviewer will edit adds it to that FR's `owns:` in the same commit.
  - (g) Phrase: "branch literal". When an FR sets a resolution rule, check later FRs that name the same branch literal against it.
  - (h) Phrase: "`index-specs.py --validate`". Run `python scripts/index-specs.py --validate` before committing a DEC.
  - (i) Phrases: "one `revises` target", "two DECs". A DEC has one `revises` target, so a resolution touching two FRs needs two DECs.

  The command contains none of the phrases FR-0012 confines to the conduct sources ("never end your turn with a question", the live-data-anchor phrases). Verified by phrase assertions and the existing FR-0012 exclusivity tests, unedited.

- **AC-4:** **The orchestrator command carries the brief-and-budget rules.** `template/.agent-team/commands/orchestrator.md` gains one section, outside `## Headless conduct`, placed after "**Phase 4: Synthesis**" and before "**Hard limits:**". Each bullet contains its operative phrases:
  - (a) Phrases: "range of free DEC numbers", "non-overlapping". Hand each Architect escalation a range of free DEC numbers read from `specs/decisions/` at brief time, non-overlapping across passes that run in parallel.
  - (b) Phrase: "at cycle 2". Report the Dev↔Reviewer cycle count to the human at cycle 2, before dispatching round 3.
  - (c) Phrase: "no discretion". A final-round brief leaves the Developer no discretion: numbered steps, exact signatures, and explicit verdict rules for the Reviewer.
  - (d) Phrase: "3-4x". Budget the last FR of a chain that shares one file at 3-4x the first.
  - (e) Phrase: "explicit test-id". Write cascades as explicit test-id lists.
  - (f) Phrases: "ratified by the merge", "same commit", "explicit act". Architect-tier DECs carried on an FR's PR are ratified by the merge: flip them in the same commit as the FR's `merged` flip and say so in the message. `neil`-tier DECs need the human's explicit act.

  The FR-0012 and FR-0008 ordering pins hold unedited: "**Terminal state of a complete cycle**" < the verdict paragraph < the gate-outcomes block < "**Phase 3: Escalation routing**". Verified by phrase and placement assertions.

- **AC-5:** **The developer command carries the self-verification rule.** `template/.agent-team/commands/developer.md` gains, outside `## Headless conduct`, bullets stating:
  - (a) Phrase: "your own verification". A defect found in your own verification is fixed in this round, not left for the Reviewer.
  - (b) Phrase: "stated default". Take the FR's stated default on an Open question rather than escalating it.
  - (c) Phrases: "earlier FR's test", "escalate". Never edit an earlier FR's test that the spec contradicts; escalate instead.

  Every `_SURVIVING_LINES["developer"]` entry and FR-0006 AC-7's staging line (`test_developer_command_states_the_staging_contract`) are unchanged.

- **AC-6:** **The DEC template names the pinned-literal cost** (IDEA-0075). The `## Cascade` guidance paragraph in `template/specs/_template/DEC-XXXX-template.md` gains two sentences, in substance:
  - "If this decision changes a vocabulary, a schema or a grammar that a test pins as a literal, name each such test by id here and the command that backfills it."
  - "A spec commit that widens a pinned set turns the verification suite red on the base branch from the moment it lands; the round that clears it is part of this decision's cost."

  The template's frontmatter, its four headings and its placeholders are unchanged. `test_index_specs_dec_tr.py::test_dec_template_lists_every_field_with_type_values_default_comment` and `::test_filled_templates_validate_with_exit_0_and_no_warnings` pass unedited.

- **AC-7:** **Wrappers are regenerated, and nothing else moves.**
  - The eight wrappers for the four edited commands are regenerated by `scripts/bootstrap.py::generate_commands`, as it is after FR-0019. They are LF and equal the generator's output (`test_committed_wrappers_equal_generate_commands_output_after_lf_normalisation`).
  - No `## Headless conduct` block changes, so `_CORE_SHA256` and `_REVIEWER_SHA256` still match.
  - Every test that passed before this FR passes, except the test ids DEC-0018 and DEC-0019 name, each changed only as those DECs bound it.
  - FR-0012 AC-10's residual check is not tripped, because DEC-0016 anchors it at `f037978`.
