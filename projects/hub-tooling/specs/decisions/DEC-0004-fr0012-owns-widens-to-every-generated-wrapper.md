# DEC-0004: FR-0012's `owns:` widens to every wrapper `generate_commands` writes

## Context

FR-0012 AC-9 says "every canonical command has both wrappers, regenerated from source", names `docs.md` in its verification clause, and closes with "the committed wrappers equal the generator's output byte-for-byte". The FR's What section promises the same outcome ("every canonical command gains both wrappers — closing the gap where three of them have only one or none today"), and `solution_space.fixed` says the wrappers "are generated by `scripts/bootstrap.py::generate_commands`, never hand-edited". The `owns:` list, written narrowly because `template/.claude/commands/**` is a hub `CLAUDE.md` human-approval path, covers only the five conduct-block commands' wrappers (ten paths).

The maintainer-mode Developer implemented all ten ACs at `49e6644` and escalated under "Code outside FR scope / footprint crossing" with two facts the FR's Notes had not anticipated. First, `generate_commands` (`scripts/bootstrap.py:427`) iterates every `.agent-team/commands/*.md` and writes both wrappers for each; it has no per-command selection, so the one function AC-9 requires necessarily rewrites `architect.md`, `escalate.md`, `gate.md`, `status.md` under both harnesses and creates `docs.md` under both — ten paths outside `owns:`. Second, the drift is larger than "missing pieces": the template's checked-in wrappers for those four commands are pre-full-body stubs (`Follow the instructions in @.agent-team/commands/<name>.md.` / `Read ... and follow it exactly.`), a format the generator has not produced since `COMMAND_META` and the inlined body landed, and `.cursor/commands/docs.md` is missing as well as the `.claude` one the FR named. The Developer generated the full set to prove AC-9, reverted everything outside `owns:`, committed exactly the ten owned wrappers, and captured the out-of-`owns:` diff (372 lines, `_dispatch/FR-0012.out-of-owns-wrapper-diff.txt`).

The constraint that makes this non-obvious is the human-approval boundary. `template/.claude/commands/**` needs explicit human approval to edit; the FR's maintainer-mode convention (Notes, "Maintainer mode"; same wording in FR-0006 and FR-0008) is that the human's approval of the FR is the approval for the paths in `owns:`, granted at PR merge. Widening `owns:` widens what that approval covers. Against that: the ten added files contain no authored text at all. Each is `generate_commands` output over a canonical source this FR does not touch, plus frontmatter from `COMMAND_META` entries already merged into `scripts/bootstrap.py` under human approval. Both `bootstrap.py` create mode (line 1580) and `--upgrade` (line 1458) already run `generate_commands` after syncing the template, so every bootstrapped project — including this one, whose `.claude/commands/architect.md` is already the full-body form — has carried exactly these files since the generator changed. The template's stale stubs are never what a project runs; they are what `--upgrade` diffs *against* before regenerating, which is why every `--upgrade` of every project today reports eight spurious `~ .claude/commands/<name>.md (updated)` lines (or, interactively, eight `CHANGED:` prompts showing a diff that reverts the project's good wrapper to a stub, which the regeneration step then silently undoes).

## Decision

FR-0012 is revised in place (`version: 2`, `breaking: true`, `last_breaking_revision: 2`):

1. **`owns:` gains ten explicit paths**: `template/.claude/commands/{architect,docs,escalate,gate,status}.md` and `template/.cursor/commands/{architect,docs,escalate,gate,status}.md`. With the ten already listed, FR-0012 now owns every wrapper `generate_commands` writes for the ten canonical commands. The five canonical *sources* for those commands stay out of `owns:` and unchanged (Out of scope bullet 3, reworded to say so).
2. **AC-9's verification clause** now reads: verified for all twenty wrapper paths this FR owns — both harnesses for each of the ten canonical commands — and "byte-for-byte" is qualified: byte-for-byte after normalising `\r\n` to `\n` on a host where `generate_commands` emits CRLF. That qualification records the Developer's finding (the generator calls `Path.write_text` without `newline="\n"`, the FR-0007 defect class, which FR-0007 did not cover because `generate_commands` lives in the hub script `scripts/bootstrap.py`) without making it this FR's to fix — Out of scope already forbids changing `generate_commands`. The fix is routed to the hub-script LF item IDEA-0063 (same class, same maintainer-mode home; see FR-0012 Notes).
3. **The Notes "Regenerate, don't hand-edit"** describe the drift as it actually is (four stub-format wrappers under each harness, `docs.md` missing under both) rather than the three gaps the v1 text named.
4. **Human approval.** The ten added paths are ratified by Neil at the FR-0012 PR merge, exactly as the ten already in `owns:` — the PR diff shows every byte. Nothing else in the approval changes: no canonical source body, no role file, no permission list, no dispatcher code, no `scripts/bootstrap.py` line.

`breaking: true` under ADR-0001 rule 4: the implementation at `49e6644` does not satisfy AC-9 v2 (ten owned files are absent) and a Developer round 2 must add them. `tier: neil`: the revision widens the write surface of a maintainer-mode FR into hub `CLAUDE.md` human-approval paths; recorded `proposed`, live for the design per ADR-0001 rule 8 and the indexer's `LIVE_DEC_STATUSES`, ratified when Neil merges the PR this DEC rides on. Rule 5 was checked and does not apply — FR-0012's identity (headless conduct in the dispatched commands, with wrappers regenerated from source) is unchanged; the footprint metadata catches up with what AC-9 always required.

The Architect chose not to escalate the widening to Neil ahead of merge (the headless rule in the dispatch brief) for four reasons, recorded so the next agent facing the same boundary can apply the same test: the paths are the same directories and the same generated class as the ten the FR already writes; the files carry no authored text and no policy — an agent reading them sees exactly the canonical source it would have been pointed at by the stub; the outcome is the one the FR's What section promised when Neil confirmed the promotion on 2026-09-20; and the cost of a wrong call is bounded — Neil drops ten files from the PR at review, or rejects this DEC, and FR-0012 v1's ten wrappers stand on their own.

## Alternatives considered

- **Keep `owns:` as written, reword AC-9 to "proven in a throwaway", park the drift as a follow-up.** Rejected: it leaves the FR's What section promising an outcome the PR does not deliver, leaves the template carrying wrappers in a format `generate_commands` cannot produce (contradicting `solution_space.fixed`'s "never hand-edited" — the stubs are, in effect, hand-authored), keeps the eight spurious `--upgrade` prompts, and makes FR-0008 AC-12's "regenerated by the bootstrap renderer" raise this exact escalation again on the next maintainer-mode run. The saving is one mechanical Developer round.
- **Open a separate maintainer-mode FR for the ten remaining wrappers.** Rejected: an FR — draft, dispatch, review, PR, human merge — for ten files of pure generator output is more ceremony than the change, and the footprint question would be identical there. The footprint-driven escalation patterns in the architect role file favour making the graph linear; the linear form here is one FR that owns what its own generator writes.
- **Two globs instead of ten explicit paths.** Rejected: FR-0009 derives Developer grants from `owns:` globs, so a glob would also grant a wrapper the template gains later (FR-0008's `gate-review.md`) to this FR, and the human reviewing the widened footprint should see ten names, not a pattern. Explicit paths are consistent with the twenty entries the FR already lists.
- **Escalate to Neil before, rather than at, merge.** Rejected for the four reasons in the Decision; the human-approval convention this project already runs on (FR-0006, FR-0008, FR-0012 Notes) is approval at merge for `owns:` paths of a maintainer-mode FR, and the added paths are of the same class and directories as the existing ones.
