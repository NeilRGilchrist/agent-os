# DEC-0022: Revalidate resolves generated-file conflicts; an inherited `REVIEW.md` is not the Reviewer's own

## Context

**AC-7 conflicts.** `_finalize_revalidate_stale_branch` merges `origin/main` into the implementation worktree with an ordinary merge. AC-7 says "a merge conflict … is one `ERROR` line, a non-zero exit, no push, and the worktree left with the conflict in place for a human". Two paths conflict predictably:
- `specs/INDEX.md` is generated. Both sides regenerate it, and the resolution is always "regenerate" (hub-tooling wave-1 learnings, FR-0011/FR-0012/FR-0014 sections). The wave-2 plan §5 already makes it the Orchestrator's rule.
- The root `REVIEW.md` is committed per FR. Once one FR's review has landed on `main`, each later FR's branch conflicts with it, and the resolution is always "take the branch's side" (wave-2 plan §5).

The IDEA-0079 audit confirmed that the one existing conflict test, `test_dispatch_postapprove.py::test_merge_conflict_is_one_error_no_push_and_the_conflict_is_left_for_a_human` (L1368), conflicts on `README.md` only. No existing fixture conflicts on either file.

**AC-2 ownership.** AC-2 keeps a `REVIEW.md` "when the Reviewer committed or staged its own". `_existing_review_md_source` treats any `REVIEW.md` present on the Reviewer branch as its own. The audit, and Project A's `main` (which already carries a root `REVIEW.md` from FR-0004), show the failure. Every Reviewer branch cut from `main` after that inherits the file. Finalize prints `REVIEW-KEPT` for a review of a different FR, and `_prepare_dev_worktree_for_rework`'s precondition passes on it.

## Decision

1. **AC-7's conflict rule gains one carve-out.** When the `origin/main` merge conflicts and **every** conflicted path is `specs/INDEX.md` or `REVIEW.md`, the dispatcher resolves the conflict instead of leaving it:
   - `REVIEW.md` takes the branch's side (`git checkout --ours -- REVIEW.md`).
   - `specs/INDEX.md` is regenerated by the **worktree's** `scripts/index-specs.py`, run with `cwd=<wt>`. The indexer roots itself from its own file, so the dispatcher's copy would rewrite a different tree.
   - Both paths are staged, and the merge is concluded with `git commit --no-edit`: a two-parent commit, never `merge --continue`, `reset`, `checkout -f` or a new merge invocation. This matters because `test_no_git_argv_rewrites_history_and_every_merge_is_ff_only_or_the_ac7_exception` scans the AST for those argv literals.
   - One line tagged `MERGE-RESOLVED` names each path and how it was resolved.

   The post-merge gate re-run then proceeds exactly as today. The carve-out does not apply, and today's `ERROR` holds with the conflict left in place, in any of these cases:
   - any other path conflicts;
   - `INDEX.md` conflicts and the worktree has no `scripts/index-specs.py`;
   - the indexer exits non-zero.

   A **clean** merge is unchanged: nothing is regenerated after it. DEC-0011's "the dispatcher's own observation writes nothing" is unaffected, since the regeneration is part of concluding the merge, not of observing it.

2. **AC-2's "its own" is made precise.** A `REVIEW.md` on the Reviewer branch or in its index counts as the Reviewer's own unless its content is byte-identical to `REVIEW.md` at `git merge-base claude/rev-<FR> main`. `main` is the local branch every role worktree is cut from, which works in repositories with no `origin`. An inherited, unchanged file is treated as absent: the synthesised review replaces it (`REVIEW-WRITTEN`), with one `WARN` saying the file was inherited from `main`. When no merge-base can be computed, today's rule applies. Consequences:
   - Re-runs stay idempotent, because a Reviewer-written or synthesised file differs from the merge-base.
   - Round 2 keeps round 1's review when the round-2 Reviewer writes none. That is this FR's own review; FR-0022 asks the Reviewer to write one each round.

**`breaking: true`.** `_finalize_revalidate_stale_branch` and `_existing_review_md_source` must change, although no existing test's expectation moves. FR-0013 goes to `version: 7`, with `revisions` gaining DEC-0022 and `last_breaking_revision: 7`. Rule 5 was checked: identity unchanged.

**Why `architect`.** Both halves are mechanical completions of rules FR-0013 already states. Decision 1 automates the resolution the Orchestrator's standing brief already prescribes. Decision 2 implements AC-2's own word, "own", correctly. Neither widens any role's reach or changes a verdict. It ratifies at FR-0018's merge.

## Alternatives considered

- **Also regenerate INDEX.md after every clean merge.** Rejected. It contradicts DEC-0011, and it moves the parent and commit-count pins of `test_revalidate_merges_origin_main_with_a_two_parent_commit_and_regates` (L1317), `test_pr_opened_cites_the_post_merge_gate_run_and_reflects_the_merged_head` (L1472) and `test_revalidate_writes_nothing_so_the_worktree_stays_clean_for_the_fast_forward` (L1563). CI tests the merge ref, whose `INDEX.md` is a textual merge. That is correct whenever the two sides touched different rows, and agent rows no longer change the metrics section on a branch (DEC-0021).
- **A per-FR review path.** Rejected for this FR. It would remove the `REVIEW.md` conflict outright, but it cascades through DEC-0001, FR-0006 AC-6, FR-0013 AC-2, the rework precondition, FR-0008's evidence readers, the reviewer command, and a 919-line test file. It is recorded as an Open question on FR-0018.
- **Ownership measured against the implementation branch tip.** Rejected. The approve fast-forward and the rework sync make that three-dot diff empty, so the Reviewer's own file would be overwritten on every re-run. Five existing tests would go red (`test_dispatch_review_artifact.py` L394 and L422; `test_dispatch_postapprove.py` L479, L740 and L2428).
- **Automatic revalidate.** Rejected here. It reverses AC-7's Open-question default and moves five pinned tests (`test_dispatch_postapprove.py` L1289 certain; L1757, L1770, L1783, L2159 likely). CI already tests the merge ref, so the stale red it targets is refreshed by any push.
